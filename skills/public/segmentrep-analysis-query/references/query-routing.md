# 查询路由

这个 skill 只面向 Segmentrep v2 问数产品。默认只使用两张最终查询表。

## 1. 标准问数入口

主表：

- `segmentrep_analysis_v2."数据宽表"`

适用问题：

- 当前、今年、当年、最新、本年、现在、目前
- 标准架构、标准科目
- 事业群、事业部、产线等指定层级问数
- 跨年趋势、同比、成长趋势
- Actual / Budget / Forecast 对比
- 达成率、成长率、PBT%
- 经营情况、事业群横向对比
- 标准数由哪些原始架构或原始科目组成

关键原则：

- 问哪一层架构，就用 `"标准架构层级"` 限定哪一层。
- 查不到就说明该层级没有匹配数据，不自动用子层级汇总补数。
- `数据宽表` 已同时保留标准架构、原始架构、标准科目、原始科目，可用于大多数问数和轻量来源解释。

## 2. 原始问数入口

主表：

- `segmentrep_analysis_v2."原始YTD事实表"`

适用问题：

- `Total`、总计、总盘子、总损益
- 历史块头名称
- 历史原始科目名称
- 原始报表还原
- 用户明确说“原始架构”“原始口径”“原表”

关键原则：

- 原始表回答“Excel 原来这块是什么数”。
- 标准趋势、标准 ABF、标准架构横向对比默认不用原始表硬算。

## 3. 来源解释

默认仍查：

- `segmentrep_analysis_v2."数据宽表"`

可解释字段：

- `原始架构名称`
- `原始架构层级`
- `原始架构键`
- `原始科目列表`
- `来源记录数`

这些字段是文本，不是 PostgreSQL 数组。若包含多个值，通常用分隔符串联，回答时可转成自然语言列表。

## 4. 混合问题

横向经营表常见混合：

- `Total` 列：查 `原始YTD事实表`
- `TUC/TUB/长润发/Factory/TU-HQ/I8-TU`：查 `数据宽表`

回答时说明 `Total` 是原始总计口径，其余是标准架构口径。
