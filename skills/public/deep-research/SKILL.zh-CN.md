# 深度研究技能

## 概览

这个技能提供一套用于进行系统化网页研究的方法论。**在开始任何内容生成任务之前，先加载这个技能**，以确保你能从多个角度、不同深度和多种来源中收集到足够的信息。

## 何时使用这个技能

**在以下情况下始终应优先加载此技能：**

### 研究类问题
- 用户询问“什么是 X”“解释 X”“研究 X”“调查 X”
- 用户希望深入理解某个概念、技术或主题
- 问题需要当前、全面、且来自多个来源的信息
- 单次网页搜索不足以支撑高质量回答

### 内容生成前的预研究
- 创建演示文稿（PPT / 幻灯片）
- 创建前端设计或 UI 原型
- 撰写文章、报告或文档
- 产出视频或多媒体内容
- 任何需要真实世界信息、案例或最新数据支撑的内容

## 核心原则

**绝不要仅凭通用知识直接生成内容。** 输出质量直接取决于研究的质量和覆盖面。一次搜索查询**绝对不够**。

## 研究方法论

### 第一阶段：广泛探索

先用较宽泛的搜索理解整体版图：

1. **初步扫描**：搜索主题本身，建立整体背景认知
2. **识别维度**：根据初步结果找出值得深入研究的子主题、关键角度和相关方面
3. **绘制版图**：记录不同立场、利益相关方和可能存在的观点差异

示例：
```
主题：“医疗中的 AI”
初始搜索：
- "AI healthcare applications 2026"
- "artificial intelligence medical diagnosis"
- "healthcare AI market trends"

识别出的维度：
- 诊断型 AI（影像、病理）
- 治疗推荐系统
- 行政流程自动化
- 患者监测
- 监管环境
- 伦理问题
```

### 第二阶段：深入挖掘

针对每个重要维度做更聚焦的研究：

1. **精确查询**：为每个子主题设计更具体的关键词
2. **多种表述**：尝试不同关键词组合和不同措辞方式
3. **抓取全文**：对重要来源阅读完整内容，而不是只看摘要片段
4. **顺藤摸瓜**：当资料提到其他关键资源时，继续检索并跟进

示例：
```
维度：“放射影像中的诊断型 AI”
定向搜索：
- "AI radiology FDA approved systems"
- "chest X-ray AI detection accuracy"
- "radiology AI clinical trials results"

然后完整阅读：
- 关键论文或论文综述
- 行业报告
- 真实世界案例研究
```

### 第三阶段：多样性与验证

通过不同类型的信息确保研究足够全面：

| 信息类型 | 目的 | 示例搜索 |
|---------|------|---------|
| **事实与数据** | 获取客观证据 | "statistics"、"data"、"numbers"、"market size" |
| **案例与示例** | 获取真实应用场景 | "case study"、"example"、"implementation" |
| **专家观点** | 获取权威分析 | "expert analysis"、"interview"、"commentary" |
| **趋势与预测** | 理解未来走向 | "trends 2026"、"forecast"、"future of" |
| **比较信息** | 获得对比与上下文 | "vs"、"comparison"、"alternatives" |
| **挑战与批评** | 保持平衡视角 | "challenges"、"limitations"、"criticism" |

### 第四阶段：综合检查

在开始内容生成前，确认以下问题：

- [ ] 是否至少从 3 到 5 个不同角度完成了搜索？
- [ ] 是否已经完整阅读了最重要的来源内容？
- [ ] 是否掌握了具体数据、案例和专家观点？
- [ ] 是否同时覆盖了正面价值与限制、挑战？
- [ ] 信息是否足够新、且来自权威来源？

**如果任一项答案是否定的，就继续研究，不要急于生成内容。**

## 搜索策略技巧

### 高效查询模式

```
# 查询中要带上具体上下文
❌ "AI trends"
✅ "enterprise AI adoption trends 2026"

# 增加权威来源提示词
"[topic] research paper"
"[topic] McKinsey report"
"[topic] industry analysis"

# 搜索特定类型内容
"[topic] case study"
"[topic] statistics"
"[topic] expert interview"

# 使用时间限定词——始终使用 <current_date> 中的真实当前年份
"[topic] 2026"   # ← 替换为真实当前年份，不要写死过去年份
"[topic] latest"
"[topic] recent developments"
```

### 时间意识

**在构造任何搜索词之前，始终先检查上下文中的 `<current_date>`。**

`<current_date>` 会提供完整日期：年份、月份、日期和星期（例如 `2026-02-28, Saturday`）。根据用户问题选择合适的时间精度：

| 用户意图 | 所需时间精度 | 查询示例 |
|---|---|---|
| “今天 / 今早 / 刚发布” | **月 + 日 + 年** | `"tech news February 28 2026"` |
| “这周” | **周范围** | `"technology releases week of Feb 24 2026"` |
| “最近 / 最新 / 新的” | **月份** | `"AI breakthroughs February 2026"` |
| “今年 / 趋势” | **年份** | `"software trends 2026"` |

**规则：**
- 当用户询问“今天”或“刚发布”的内容时，查询中要使用**月 + 日 + 年**，这样更容易获取当天结果
- 在需要按天精确检索时，不要只写年份——`"tech news 2026"` 无法有效找到今天的内容
- 尝试多种表述：数字形式（`2026-02-28`）、书面日期（`February 28 2026`）以及相对时间词（`today`、`this week`）

❌ 用户问“今天科技圈有什么新消息” → 搜索 `"new technology 2026"` → 很可能错过当天信息
✅ 用户问“今天科技圈有什么新消息” → 搜索 `"new technology February 28 2026"` + `"tech news today Feb 28"` → 更容易得到当天结果

### 何时读取完整网页内容

在以下情况下应阅读完整网页内容：
- 搜索结果看起来高度相关且来源权威
- 你需要的不只是摘要片段，而是详细信息
- 来源中包含数据、案例研究或专家分析
- 你希望完整理解某个结论的上下文

### 迭代式优化

研究是一个迭代过程。完成初步搜索后：
1. 回顾目前学到的内容
2. 找出仍然存在的理解空白
3. 形成更有针对性的后续查询
4. 重复这一过程，直到覆盖足够全面

## 质量标准

当你可以有把握地回答以下问题时，说明研究已经比较充分：
- 关键事实和数据点是什么？
- 是否有 2 到 3 个具体的真实世界案例？
- 专家如何评价这个主题？
- 当前趋势和未来方向是什么？
- 面临哪些挑战或限制？
- 为什么这个主题在当下值得关注？

## 常见错误

- ❌ 只搜 1 到 2 次就停止
- ❌ 只看搜索结果摘要，不阅读全文
- ❌ 只研究一个维度，忽略主题的多面性
- ❌ 忽略反面观点、限制或批评
- ❌ 在明明有更新信息的情况下使用过时资料
- ❌ 研究尚不充分就开始生成内容

## 输出目标

完成研究后，你应当具备：
1. 对主题的多角度、系统性理解
2. 具体事实、数据点和统计信息
3. 真实世界案例和案例研究
4. 专家观点与权威来源支撑
5. 当前趋势和相关背景上下文

**只有在这些信息准备充分之后，才开始内容生成**，并基于已收集的信息产出高质量、信息充分的内容。
