# 使用 `data-analysis` skill 的工作流

本文件用于约束 `member-ops-report-planner` 如何借助 `data-analysis` skill 做结构观察和 SQL 分析。

## 总原则

- 先结构，后口径
- 先验证字段，再写 SQL
- 先判定支持范围，再组织页面

## 第一步：结构观察

对每个输入文件先做 `inspect`，目标是拿到：

- sheet / table 列表
- 每个表的列名
- 数据类型
- 非空情况
- 样例值
- 行数

这一阶段需要回答的问题：

1. 哪张表最像会员主表
2. 哪张表最像门店维表
3. 哪张表最像活动明细表
4. 哪张表最像专题汇总表

## 第二步：候选表筛选

识别候选会员主表时，优先寻找同时具备以下特征的表：

- 行数较大
- 有会员唯一标识列
- 有身份、等级、年龄、性别中的多个字段
- 有门店归属列
- 有消费、活动、行为类字段

识别候选门店表时，优先寻找：

- 一行一个门店
- 有门店编码
- 有门店名称
- 有门店类型
- 有门店状态
- 有门店汇总指标

识别活动明细表时，优先寻找：

- 一行一条活动参与记录
- 有会员编码
- 有活动名称或活动类型
- 有日期或月份
- 有门店编码

## 第三步：字段验证

不要只看列名，要做值域验证。

### 示例：识别会员唯一标识

候选列命中词典别名后，还要验证：

- 非空率高
- 去重后接近总行数
- 值形态稳定

### 示例：识别门店类型

除了列名，还要看样例值是否类似：

- `专卖店`
- `涂装服务中心`
- `别墅之星体验店`
- `普通金牌店`

### 示例：识别一物一码来源标记

除了列名，还要检查值域是否像：

- `是/否`
- `1/0`
- `true/false`

## 第四步：SQL 聚合方式

只有在字段映射已经确认后，才允许写 SQL 聚合。

建议优先使用以下查询类型：

- 行数和去重校验
- 分类分布
- 主题级聚合
- 月度聚合
- 门店/会员双维度聚合

## 第五步：证据记录

每次关键字段映射都要记录证据：

- 原始文件
- 原始 sheet
- 原始字段
- 值样例
- 判定理由

每次关键指标聚合都要记录：

- 使用了哪个表
- 使用了哪些字段
- 聚合维度是什么
- 是否存在口径限制

## 推荐查询思路

### 结构核对类

- 统计每张表行数
- 查看候选主表前 5 行
- 查看候选主表各字段非空率
- 查看关键字段唯一值分布

### 主题计算类

- 会员概况：按身份、年龄段、等级聚合
- 一物一码：按门店、按工种聚合
- 消费：按会员、按门店类型、按等级聚合
- 会员日：按月份、按等级、按店型聚合
- GMV：先判断是否有月度明细，再决定是否只出年累计

## 必须避免的错误

- 看见类似字段名就直接使用
- 在结构未确认前直接出结论
- 把专题汇总表当成唯一事实来源
- 把年度总额误当月度明细
- 把门店汇总口径和会员去重口径混用却不标注
