# 数值格式与汇报样式指南

本文件约束 `member-ops-report-planner` 的第二层报告内容如何表达，帮助下游 PPT / HTML / PDF / 图表技能生成更适合正式汇报的结果。

## 总原则

- 准确优先，视觉其次
- 数值格式要稳定，不能同一页混用口径
- 明细表格要控制密度，避免把原始宽表直接塞进报告
- 颜色与样式只能作为 `render_hints` 输出，不在本 skill 内直接渲染最终页面

## 数值格式

### 人数 / 次数 / 门店数

- 默认保留整数
- 使用千分位分隔
- 示例：`12,826人`、`275次`、`8家`

### 金额

根据原始单位决定：

- 原始字段单位为元：默认展示为元、万元或百万元，视数值大小而定
- 原始字段单位为千元：计算时保留原始单位，展示时可转为万元或元，但必须在 `method_notes` 中注明

推荐：

- 小额或客单价：展示为 `元`，保留 0 位小数
- 总金额：展示为 `万元`，保留 1 位小数；如用户要求可保留到整数
- GMV：必须说明是成交金额、成交额还是商城成交金额

### 百分比

- 默认展示为百分比 `%`
- 常规占比保留 1 位小数
- 页面标题或强结论中可四舍五入为整数百分比
- 计算字段保留原始比例值和展示值，例如：
  - `value = 0.663`
  - `display = "66.3%"`

### 均值 / 客单价 / 人均贡献

- 人均金额默认保留整数元
- 平均次数默认保留 1 位小数
- 平均年龄默认保留 1 位小数

## 表格排版

### 明细表格

明细表格不应无限展开。

推荐：

- PPT：单页建议 6-10 行
- HTML：可展示更多，但仍应有 Top N 和合计
- PDF：优先分页或拆表

### 必须提供的表格提示

每个表格 section 建议包含：

- `recommended_rows`
- `recommended_columns`
- `has_total_row`
- `highlight_rules`
- `sort_by`
- `table_density`

### 合计行

以下表格默认建议带合计行：

- 一物一码门店表
- 待挂靠工种表
- 待挂靠区域表
- 会员等级消费贡献表
- 基检门店表
- 会员日等级参与与核销表

### 列名

- 面向汇报的列名要短
- 原始字段名可放在 `method_notes` 中
- 不建议在报告表格里直接使用过长的 Excel 字段名

## 图表建议

### 适合柱图

- 年龄分布
- 等级分布
- 月度趋势
- 门店排名

### 适合折线图

- 月度 GMV
- 月度参与人数
- 月度活动场次

### 适合漏斗 / 路径图

- 会员总盘 -> 一物一码 -> 会员日 -> 消费 -> 高等级
- 线上行为 -> 线下消费 -> 高价值会员

### 不建议绘图

- 字段缺失导致的弱口径
- 样本过少的分类
- 只有 1-2 个类别的分布

## 视觉重点

`report_plan.json` 中应通过 `render_hints` 提醒下游渲染：

- 哪些指标是主 KPI
- 哪些表格行需要突出
- 哪些字段可以用强调色
- 哪些结论适合放在页脚洞察

推荐视觉方向：

- 主色：品牌红、深蓝、深灰等稳重高对比色
- 强调色：用于异常、机会、增长、风险
- 避免全页都是同一种颜色
- 表格用浅底色区分表头和合计行
- Top 1 / Top 3 可用轻量强调，不要过度装饰

## 输出层边界

本 skill 只输出结构、数据、样式意图和渲染提示。

禁止在本 skill 中：

- 直接生成最终 HTML
- 直接生成最终 PPT
- 直接生成最终 PDF
- 把字段映射、业务计算、最终渲染塞进一个单体脚本

正确做法：

- 本 skill 输出 `report_plan.json`
- 图表 skill 根据图表任务绘图
- PPT / HTML / PDF skill 根据 `report_plan.json` 渲染最终产物
